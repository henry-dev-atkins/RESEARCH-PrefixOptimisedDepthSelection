## Project Teaching Summary

### Philosophy

- PODS is an empirical research repo with a strict preference for simple, config-driven execution.
- Static deployable prefixes are the core idea; dynamic early exit is explicitly out of scope.
- Measured deployment cost is mandatory. FLOP-only claims are out of bounds.
- Unsupported runtimes must fail loudly, especially CPU execution for ML runs.
- Config should own experiment behaviour; ad hoc hidden logic is against repo policy.

### Core Goal

Train one over-depth model whose prefixes are valid standalone deployable models, then select the shallowest prefix that meets a held-out quality target under a measured cost constraint.

### Scientific Boundary

- The defensible claim is a one-training-run to many-static-prefixes deployment frontier.
- PODS must be compared against strong static baselines such as naive truncation and independently trained shallow models.
- Mixed results are acceptable; overstated wins are not.

## Repo Reality

### Main Entrypoint

- `uv run python -m pods.run --config <config-path>`
- CLI loader: `pods/src/pods/run.py`

### Main Config Surface

- `pods/configs/sanity/`
- `pods/configs/cifar/`
- `pods/configs/glue/`
- Runtime schema and validation: `pods/src/pods/config/schema.py`

### Main Run Flow

1. `pods/src/pods/run.py` loads a YAML config and hands it to `run_experiment`.
2. `pods/src/pods/experiments/runner.py` enforces CUDA, builds datasets, loaders, model, optimiser, training, evaluation, benchmarking, and depth selection.
3. `pods/src/pods/training/loops.py` handles multi-depth training.
4. `pods/src/pods/eval/quality.py`, `benchmark.py`, and `select.py` produce per-prefix quality and cost evidence.
5. `pods/src/pods/experiments/reporting.py` and `pods/src/pods/eval/summarise.py` persist raw runs and regenerate processed summaries.

### Main Reporting Flow

- Matrix completeness tracking: `pods/src/pods/experiments/matrix_status.py`
- Figure generation from processed summaries: `pods/src/pods/eval/review_figures.py`
- Paper table export from processed summaries: `pods/src/pods/eval/export_paper_assets.py`

### Main Output Paths

- Raw run artefacts: `pods/results/raw/`
- Processed summaries and reporting outputs: `pods/results/processed/`
- Manuscript-facing generated tables: `paper/generated/`
- Temporary and exploratory artefacts: `temp/`
