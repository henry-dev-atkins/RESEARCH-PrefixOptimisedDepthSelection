## Project Teaching Summary

### Philosophy

- PODS is a research codebase, not a product codebase: the standard is scientific evidence, not feature breadth.
- The central idea is static prefix deployment. A trained over-depth model exposes multiple deployable prefixes, then a fixed prefix is selected offline using held-out quality and real measured hardware cost.
- Dynamic early exit, per-example routing, hidden-state shortcuts in benchmarking, training-set selection, FLOP-only cost claims, and silent CPU fallback are spec violations.
- Configs own experiment behaviour. New behaviour should be visible in config/schema rather than hidden in runner logic.
- The repo favours simple, current-state implementation over compatibility layers or legacy support.

### Core Goal

Train one over-depth model whose prefixes are valid standalone models, benchmark extracted prefixes, and select the shallowest prefix satisfying a validation-quality target under a measured deployment-cost constraint.

### Evidence Standard

- Quality must come from validation/final-held-out splits, not training accuracy.
- Cost must be measured from extracted prefixes: p50/p95 latency, throughput, peak GPU memory, and model file size.
- CUDA/GPU execution is required for ML runs; unsupported device situations must fail loudly.
- Strong baselines remain mandatory: full model, independently trained shallow models, naive truncation, LayerDrop-style depth robustness, progressive shrinking/OFA-style baseline, and distillation where relevant.

## Repo Understanding

### Main Entrypoint

- `uv run python -m pods.run --config <config-path>`
- CLI module: `pods/src/pods/run.py`

### Main Config Files

- `pods/configs/sanity/`
- `pods/configs/cifar/`
- `pods/configs/glue/`
- Schema and runtime validation: `pods/src/pods/config/schema.py`

### Main Run Flow

1. `pods/src/pods/run.py` loads YAML config.
2. `pods/src/pods/experiments/runner.py` enforces device/runtime constraints, builds datasets/loaders/models, runs training/evaluation/benchmarking, and writes raw evidence.
3. `pods/src/pods/training/loops.py` handles multi-depth training objectives.
4. `pods/src/pods/eval/quality.py`, `benchmark.py`, and `select.py` provide validation quality, measured costs, and selection.
5. `pods/src/pods/experiments/reporting.py` persists raw runs.

### Main Reporting Flow

- Matrix status: `pods/src/pods/experiments/matrix_status.py`
- Processed summaries: `pods/src/pods/eval/summarise.py`
- Review figures: `pods/src/pods/eval/review_figures.py`
- Paper table export: `pods/src/pods/eval/export_paper_assets.py`

### Main Output Paths

- Raw durable runs: `pods/results/raw/`
- Processed durable summaries: `pods/results/processed/`
- Paper-facing generated assets: `paper/generated/`
- Temporary caches and exploratory outputs: `temp/`
- Agent plans/handovers/learnings/TODO: `AI_SPACE/`
- Archived clutter or invalid generated artefacts: `archive/`
